# Демонстрация MVP

Из корня проекта запустите `bash data_review/defense_mvp/demo.sh /tmp/defense-demo-rerun`. [Скрипт](demo.sh) содержит полные команды с закреплёнными версиями и выполняет их из распакованного снимка. Для DPO нужны PDF и bare Git в /tmp/defense-inputs/dpo, для CSD — в /tmp/ind-eval/csd, для LoRA — в /tmp/mvp-inputs/lora. Версии и SHA-256 берутся из соответствующих прежних манифестов. [DPO](../final_evaluation/cases.tsv) · [CSD](../independent_evaluation/cases.tsv) · [LoRA](../mvp_portability/cases.tsv)

1. **DPO, потенциальное расхождение.** Команда DPO из demo.sh указывает диалог Anthropic HH, Pythia-2.8B, приложение B и аргументы Hydra. Ожидается `potential_discrepancy`, PDF 0.000001 и код 0.0000005. Покажите страницы 9 и 20, README:85, config/config.yaml:51 и trainers.py:276–277. LR относится к базовой настройке перед прогревом, а JSON требует подтверждения эксперта. [Проверенный JSON](demo_runs/dpo.json)
2. **CSD, совпадение тестового угла.** Команда CSD из demo.sh задаёт этап Rotation tasks, Rotated MNIST и домен 90. Ожидается `match`, 90 / 90. Покажите связку страниц 6–7 и rotation/ResNet.py:10,100–107,390–409. Фактический поворот проходит через full_test_x и батчи в feed_dict. [Проверенный JSON](demo_runs/csd.json)
3. **LoRA, обоснованный отказ.** Команда LoRA из demo.sh выбирает табл. 9, RoBERTa-large LoRA, CoLA и опубликованный shell-рецепт. Ожидается `insufficient_materials`, PDF 0.0002 и верхнеуровневый code_value=null. Покажите строку Learning Rate на стр. 19, значение 0.0003 в доказательствах кода, AdamW и батч 4 × 8 × 1 = 32. Семантика Batch Size в таблице и принадлежность скрипта к её варианту не установлены. Это объясняет, почему двух чисел недостаточно для сигнала. [Проверенный JSON](demo_runs/lora.json)
